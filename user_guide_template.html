Section 1: System Overview & Core Capabilities

The CDN Fire Engineering ERP System is a specialized Enterprise Resource Planning and Inventory solution tailored specifically for fire protection engineering, sprinkler/alarm system installations, fire extinguisher servicing, and construction project logistics.

Key Features at a Glance

  • FIFO Inventory Control: Real-time First-In, First-Out batch valuation ensuring exact unit costs, manufacture/expiry date tracking, and precise COGS calculations.
  • Project Logistics Pipeline: Multi-stage material request workflow (PENDING → PENDING GM → PENDING ADMIN → APPROVED → ISSUED).
  • Strict Cost Governance: Project estimate tracking with automatic alert escalation. Manual expenses exceeding budget that cause site costs to hit or exceed LKR 5,000,000 require explicit Super Admin approval.
  • Fire Extinguisher Management: Complete lifecycle management for serialized extinguisher units, customer refill service requests, temporary rental replacements, and delivery notes.
  • Tools & Capital Asset Tracking: Unique serial number tracking, assignment to engineers, maintenance condition status (New, Good, Fair, Damaged, Under Repair), and full audit history.
  • Pipe Cut Off-Cut Optimization: Tracking remaining pipe cut lengths traceable to original batch numbers to minimize material scrap and optimize site reuse.
Critical Concept — FIFO Isolation
Stock quantities are never stored as static text numbers on catalog items. Current available stock is dynamically calculated as the exact sum of active availableQty across all confirmed StockBatch records.

Section 3: Master Data Management

1. Category & Sub-Category Hierarchy

All items in the ERP belong to a 2-tier classification structure: Category (e.g., Pipes & Fittings, Sprinklers, Alarm Panels, Fire Extinguishers, Valves) and Sub-Category (e.g., Seamless Steel Pipes, CPVC Fittings, Glass Bulb Sprinklers).

  • Category names are globally unique.
  • Sub-Category names are unique within their parent category (e.g. "2 inch" can exist under both Pipes and Valves).

2. Master Inventory Catalogue

The master inventory catalog stores static product metadata:

  • itemCode: Unique alphanumeric identifier (e.g. PIP-STL-001).
  • barcode: Optional barcode string for handheld scanners.
  • minStock: Threshold level that triggers automated Low Stock alerts.
  • rackLocation & warehouse: Default physical storage bin/shelf.
  • expiryControlled: Boolean toggle. When enabled, the system enforces manufacture and expiry date inputs during stock receiving.

3. Supplier & Customer Registries

Master vendors (Suppliers) supply stock receives, while clients (Customers) are linked to Engineering Projects, Delivery Notes, and Fire Extinguisher Refill contracts.

Section 4: Warehouse & Inventory Management (FIFO)

The Goods Receive & FIFO Batching Workflow

Stock Receiving Lifecycle
1
Create Receive Header (Draft): Select Supplier, Receive Date, and Reference Invoice/PO Number.
2
Add Items & Batch Info: Enter received quantities, unit cost, batch number, rack location, and manufacture/expiry dates.
3
Confirm Goods Receive: Click Confirm. The status changes to CONFIRMED, creating immutable StockBatch records and generating StockMovement (Type: IN) entries.

FIFO Consumption Rule

When materials are issued to a project or site, the system automatically draws from the oldest available stock batch (lowest receiveDate) for that item.

Batch Available Quantity Rule
The system prevents over-issuing. If requested quantity exceeds batch 1, the system automatically splits the issue across subsequent batches (Batch 1 + Batch 2) while maintaining accurate COGS.

Immutable Stock Movement Ledger

Every inventory transaction appends a permanent row to the StockMovement table storing: Qty, MovementType (IN, OUT, RETURN, TRANSFER, ADJUSTMENT), ReferenceType, StockBatchId, and CreatedBy. Rows are never hard-deleted.

Section 5: Project Material Logistics

Project Setup & Cost Estimates

Each project is assigned a unique Code (e.g. PRJ-2026-004), Project Manager, Customer, Contract Value, and baseline Cost Estimates across 5 heads: Material, Labour, Transport, Equipment, and Other.

Material Request & Issue Pipeline

Site Material Request to Dispatch Flow
1
Site Request Creation: Site Engineer or PM creates a Material Request specifying items and quantities needed on site (PENDING).
2
General Manager Review: GM reviews request urgency and project scope (PENDING GM).
3
Admin Approval: Administrator approves or modifies approved quantities (APPROVED).
4
Warehouse Issuance: Inventory Controller picks stock from FIFO batches and issues items (ISSUED). Stock moves from Warehouse to ProjectMaterial inventory.

Material Returns & Scrap Disposal

Surplus or damaged site materials can be returned using a MaterialReturn document. Returned items are inspected and categorized as:

  • GOOD: Returned directly to main warehouse active stock batch.
  • DAMAGED: Quarantined for repair or vendor return.
  • SCRAP: Written off from active project inventory.

Section 6: Financial Control & Overrun Approvals

Real-Time Cost Tracking

The ERP automatically aggregates project actual costs:

  • Actual Material Cost: Calculated from exact unit costs of issued FIFO batches.
  • Actual Labour Cost: Calculated from assigned labour hours and daily overtime rates.
  • Actual Transport & Operational Expenses: Logged manually under project expenses.

LKR 5,000,000 Super Admin Approval Rule

To prevent unauthorized budget overruns on large commercial engineering projects, the system enforces a strict financial guardrail:

Financial Approval Threshold Rule
Whenever a new Project Expense is submitted, if the updated total actual cost of the project reaches or exceeds LKR 5,000,000:
  1. The expense status is automatically set to PENDING_APPROVAL.
  2. The expense is held in quarantine and is NOT added to the live project actual cost ledger.
  3. An alert appears in the Cost Approvals portal for SUPER_ADMIN review.
  4. Once approved by Super Admin, the status changes to APPROVED and costs are committed. If rejected (REJECTED), the expense is excluded.

Section 7: Fire Extinguisher Management Module

Serialized Unit Tracking

Fire extinguishers are high-compliance safety assets tracked by serial numbers. Units are assigned statuses: AVAILABLE, ASSIGNED, UNDER_REFILL, TEMPORARY_REPLACEMENT, DAMAGED, or RETIRED.

Customer Refill & Rental Workflow

Customer Extinguisher Refill & Replacement Process
1
Intake & Receipt: Register customer refill order (RECEIVED). Record customer details and extinguisher serial numbers.
2
Issue Temporary Replacement (Optional): If the client requires backup units while servicing, dispatch rental replacement units from main inventory.
3
Servicing & Refilling: Technician services the unit and logs pressure test/refill details (IN_PROGRESS).
4
Delivery & Swap Return: Generate Delivery Note. Return serviced client units and collect temporary replacement units back into company stock (COMPLETED).

Section 8: Tools & Equipment Management

Capital tools (e.g. Grooving Machines, Threading Machines, Pipe Cutters, Scaffolding, Core Drilling Rigs) are managed independently from consumable stock.

Tool Management Features

  • Serial Number & Barcode Tagging: Each tool has a unique toolCode and physical serialNo.
  • Condition Rating: Tracked as New, Good, Fair, Damaged, or Under Repair.
  • Assignment to Engineers: Tools are assigned to Site Engineers/Projects with an active batch status (ACTIVE → RETURNED).
  • Maintenance & Audit History: Every tool movement, repair log, or damage event appends an immutable entry to ToolHistory.

Section 9: Labour & Staff Management

Project Labour & Overtime (OT)

Site workers (Welders, Fitters, Helpers, Technicians) are assigned to active projects with designated daily rates.

  • Labour Roster: Workers can be marked as ACTIVE, RELEASED, or ON_LEAVE.
  • Overtime Logging: PMs or Engineers log daily OT hours via LabourOT entries, automatically calculating extra labour costs based on worker hourly rates.

Internal Staff Allocation

Internal system staff (Users with Engineer or PM roles) are mapped to projects via ProjectStaff, defining explicit responsibilities and site access permissions.

Section 10: Pipe Off-Cut & Wastage Optimization

In fire protection engineering, standard 6-meter pipe lengths cut on site leave valuable off-cut pieces. The ERP features a dedicated Pipe Cut Piece tracking module:

  • Traceable Lineage: Every cut piece records parentLength, pieceLength, unit, and is linked to its original stockBatchId.
  • Barcode Labeling: Off-cuts are assigned unique barcodes and rack locations for easy identification.
  • Re-issuing: Site engineers can search and issue off-cuts for shorter pipe runs before cutting full new pipes, yielding significant material cost savings.

Section 11: Reports, Analytics & Email Alerts

System Reports

  • Stock Valuation Report: Total current inventory value breakdown by Category, Warehouse, and FIFO batch cost.
  • Project Financial Variance: Side-by-side comparison of Estimated vs. Actual Costs across Material, Labour, Transport, and Equipment.
  • Stock Movement Audit Trail: Exportable chronological log of all stock movements filtered by date, reference, or user.
  • Expiry & Maintenance Alert Logs: Perishable chemical items nearing expiry date and fire extinguisher refill due dates.

Automated Email Digest

The ERP includes automated background email reporting powered by Resend and React Email. Super Admins and Managers receive weekly stock summary emails covering low stock warnings, impending expiries, and project cost highlights.

Section 12: System Administration & Troubleshooting

User Provisioning & Role Updates

  1. Navigate to Admin → Users & Roles.
  2. Click Create New User. Enter Name, Email, Employee Code, Designation, and Department.
  3. Select the appropriate System Role. The permissions matrix automatically updates granted capabilities.

Audit Log Monitoring

All sensitive operations (login attempts, role changes, financial overrides, stock receive confirmations) are recorded in the AuditLog table with user ID, timestamp, action type, and JSON metadata.

Common Operational FAQs & Troubleshooting

Q1: Why cannot I issue stock for a material request?

Answer: Ensure the material request status is APPROVED by Admin/GM. Also check if active batches exist with sufficient availableQty.

Q2: Why is my expense showing "Pending Approval"?

Answer: The expense caused the total project actual cost to reach or exceed LKR 5,000,000. It requires sign-off by a Super Admin in the Cost Approvals module.

Q3: How do I handle a returned damaged fire extinguisher?

Answer: Update the unit status to DAMAGED in Fire Extinguisher Management. Create a repair log or initiate replacement unit dispatch.
